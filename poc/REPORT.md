## 4. 발견 사항 및 PRD 반영 제안

### F1. "현재 시즌만" 집계 시 체감 데이터가 크게 줄어든다 (중요)

시즌 시작을 `2026-01-08`로 가정하면 집계 대상이 **39판 → 15판(38%)** 으로 축소된다. 해당 계정의 솔로랭크·빠른 대전 기록이 모두 2025년이기 때문.

- **제안**: PRD O8 신규 — 기간 선택 UI(이번 시즌 / 전체 / 최근 90일)를 **v1.1 필수**로 승격. v1은 "이번 시즌" 기본 + "전체" 토글 1개만 제공.
- **이유**: 신규 사용자가 계정을 등록했을 때 화면이 비어 보이는 것을 방지.

### F2. 계정마다 활동 큐가 극단적으로 다르다

한 계정 안에서도 솔로랭크는 2025년, 일반은 2026년에 몰려 있다. 4개 큐를 모두 조회하는 현재 설계는 유효하나, **큐별 조회 결과가 0건인 경우가 흔하다**.

- **제안**: 계정별 "최근 활동 큐"를 UI에 표시(예: `주 활동: 일반`), 0건 큐는 새로고침 대상에서 자동 제외.

### F3. 20경기/큐 백필로는 시즌 초반 데이터가 부족할 수 있다

일반 큐는 20경기로 2026-01-02까지 거슬러 올라갔으나, 그 이전 기록은 조회되지 않았다.

- **제안**: `start` 파라미터 기반 **"더 불러오기"** 페이지네이션을 v1.1에 추가 (PRD FR-3.6 확장).

### F4. 개발용 키 처리량이 UX의 병목

1계정 80경기 = 59초. 10계정이면 약 20분. 최초 사용자 경험이 나쁠 수 있다.

- **제안**: ① 첫 등록 시 계정당 10경기만 수집(약 10분) → ② 이후 증분 → ③ "더 불러오기"로 확장. 또는 **프로덕션 키 조기 신청**(O6).

## 5. 재현 방법

```powershell
# .env 에 RIOT_API_KEY 입력 후
node poc/collect.mjs --accounts "카레는야망입니다#KR1" --count 20

# 시즌 필터 적용
node poc/collect.mjs --accounts "카레는야망입니다#KR1" --count 20 --season-start 2026-01-08
```

출력: `poc/out/accounts.json`, `poc/out/records.json`
